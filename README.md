# terraform-provider-definednet

Terraform provider for [Defined Networking](https://www.defined.net), managing
networks, roles, tags, routes, hosts, and join keys through the
[Defined Networking API](https://docs.defined.net/api/defined-networking-api/).

Built on terraform-plugin-framework (protocol 6). Generated reference docs live
in `docs/`.

Published to the
[Terraform Registry](https://registry.terraform.io/providers/definednet/definednet)
and the
[OpenTofu Registry](https://search.opentofu.org/provider/definednet/definednet).

## Resources and data sources

| Type | Notes |
| --- | --- |
| `definednet_role` | Firewall rules per role. Renaming replaces the role (the API has no rename). |
| `definednet_tag` | Config overrides, route subscriptions, firewall rules. Position with `before` / `after`. |
| `definednet_route` | Routable CIDRs plus firewall rules with `local_cidr`. |
| `definednet_network` | IPv4 prefix is optional; the IPv6 prefix is always generated by the API. Network-wide config overrides. |
| `definednet_host` | Host records for lighthouses, relays, and other hosts whose identity must exist before they boot. |
| `definednet_join_key` | Reusable enrollment secret for fleets; the hosts it enrolls stay outside Terraform. Needs join keys enabled for the organization. |
| `data.definednet_network` | Look up a network by `id` or exact `name`. |
| `data.definednet_role` | Look up a role by `id` or exact `name`. |
| `data.definednet_route` | Look up a route by `id` or exact `name`. |
| `data.definednet_tag` | Look up a tag by `name`. |

## Configuration

```hcl
terraform {
  required_providers {
    definednet = {
      source = "definednet/definednet"
    }
  }
}

provider "definednet" {
  api_key = var.definednet_api_key # or DEFINEDNET_API_KEY
  # endpoint = "https://api.defined.net"  # or DEFINEDNET_ENDPOINT
}
```

The API key needs the `<resource>:create|read|update|delete` scopes for each
resource type it manages, plus `<resource>:list` for lookups by name in the
network, role, and route data sources. Domains use `domains:create|read|delete`
plus `domains:verify` for `definednet_domain_verification`; endpoint OIDC
providers use `endpoint-oidc-providers:create|read|update|delete`. Hosts use
`hosts:create|read|update|delete`, plus `networks:read` when `ipv4_address` is
omitted. Join keys use `join-keys:create|read|update|delete`.
Existing resources can be brought under management with `terraform import`;
see the import examples in `docs/`.

### Firewall rules

`firewall_rules` is a set: the API stores rules unordered and returns them
sorted by CIDR and port, so ordering in configuration is irrelevant.
Omit `allowed_role_id`, `allowed_tags`, and `port_range` to allow every role,
tag, or port. `allowed_tags = []` means the same thing to the API as omitting
it, and the API always reports it back as null; the provider rejects an empty
set so the plan and the refreshed state agree.
In a `definednet_role`, `allowed_role_id = "self"` allows hosts with that same
role, since Terraform does not let a resource reference its own `id`. It is the
only accepted spelling of the role's own ID, and the resource reports it back
as `self`, so copying one role's `firewall_rules` into another role grants the
copy's own hosts. Use the `definednet_role` data source to read literal IDs.

### Enrolling hosts

There are two ways to put machines on a network:

- **Join keys** for fleets. A `definednet_join_key` is a reusable secret scoped
  to a network, role, and tags; every machine that enrolls with it becomes a
  new host named after its hostname. Terraform manages the key, not the hosts. The
  token is stored (sensitive) in state and is returned only on create, so it
  is null after import.
- **A host record** for lighthouses, relays, and pets whose identity must
  exist before they boot, for example because other config references their
  address. `definednet_host` creates the record and mints a single-use
  `enrollment_code` (sensitive, null after import) to pass to dnclient, for
  example through cloud-init. Terraform does not track enrollment.

A code dies at first use, so a rebuilt machine needs a new one: put whatever
replaces the machine, such as its AMI ID, in `enrollment_code_triggers`, and
the new code flows into the machine's user data in the same apply. The rebuilt
machine takes over the existing host record; the previous machine's certificate
is not revoked, so run one machine per host.

### Endpoint OIDC client secrets

The API never returns a provider's client secret, so Terraform cannot see a
secret rotated outside Terraform; every update re-sends the configured one.
Prefer `client_secret_wo` with `client_secret_wo_version` (Terraform 1.11 or
OpenTofu 1.11 and newer), which keeps the secret out of plan and state, and
bump the version when the secret rotates. `client_secret` stores the secret in
state for older Terraform.

### Config overrides

`config_overrides[*].value` is a JSON document, so wrap every value with
`jsonencode()`. Networks, tags, and hosts each carry their own overrides; a
host's win over its tags', which win over the network's.

```hcl
config_overrides = [
  { key = "lighthouse.dns.host", value = jsonencode("0.0.0.0") },
  { key = "lighthouse.dns.port", value = jsonencode(53) },
]
```

## Development

```sh
make build      # builds ./terraform-provider-definednet
make test       # unit tests against an in-memory fake API (needs a terraform binary on PATH)
make testacc    # acceptance tests against the real API (see below)
make docs       # regenerates docs/ from the schema and examples/
```

To use a local build, add a dev override to `~/.terraformrc`:

```hcl
provider_installation {
  dev_overrides {
    "definednet/definednet" = "/Users/you/go/bin"
  }
  direct {}
}
```

then `make install` and run Terraform without `terraform init`.

The tests in `internal/provider` run real `terraform` plans and applies against
`fakeapi_test.go`, which mirrors the API behaviors the provider has to handle:
rules returned in sorted order, `null` for empty tag lists, server-assigned tag
priority, reformatted JSON override values, and 403 for missing API key scopes.

### Acceptance tests

`make testacc` creates, updates, imports and destroys real objects. Run it
against an organization that holds nothing you care about; the tests run one at
a time and stay within the free plan's limits (two routes, ten networks).

| Variable | Purpose |
| --- | --- |
| `DEFINEDNET_API_KEY` | Key for the test organization, with every scope. |
| `DEFINEDNET_ENDPOINT` | Optional; defaults to `https://api.defined.net`. |
| `DEFINEDNET_ACC_DOMAIN` | Domain the verification tests verify. Defaults to `tf-acc.test.undefined.works`, whose TXT record matches only the shared test organization. Against your own organization, set a domain you control and publish the `verification_record_name` / `verification_record_value` the domain gets there. |

The join key tests skip themselves when the organization does not have join
keys enabled, which the API reports as a 404 on `/v1/join-keys`.

Every object the tests create is named with a `tf-acc` prefix. `make sweep`
deletes those, plus the `DEFINEDNET_ACC_DOMAIN` domain, if a run is interrupted.

## Releasing

Push a tag like `v0.1.0`. The release workflow builds every platform with
goreleaser, signs the checksums, and publishes a GitHub release. The Terraform
Registry ingests the release through its webhook and verifies the signature
against the public key registered under the `definednet` namespace, so the key
must be registered before the first tag. The OpenTofu Registry checks this
repository for new release tags every 15 minutes and adds them on its own;
`tofu init` then verifies the signature against the same public key, stored in
[opentofu/registry](https://github.com/opentofu/registry) under
`keys/d/definednet/`.

The signing key is an AWS KMS key and never leaves KMS. The workflow assumes a
role trusted only for `v*` tags of this repository, and goreleaser runs
`scripts/kms-sign.py`, which wraps `kms:Sign` in an OpenPGP signature. The only
GitHub secret is that role's ARN, `GPG_SIGNING_ROLE_ARN`. Creating the key and
registering its public half are documented in the ansible repo under
docs/terraform-provider-signing.md.
